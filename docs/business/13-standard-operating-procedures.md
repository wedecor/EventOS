## Purpose of This Document

This document describes **what SOPs exist today** (Current State) and **what SOPs We Decor needs** (Future Vision), across:

- Sales and customer communication
- Event execution and operations
- Staff, vendor, inventory, and finance workflows
- Marketing and customer support

It does **not** replace domain documents (`04`–`12`). Those documents remain the authoritative workflow references. **This document** tracks:

- Which areas operate on informal practice vs written SOPs
- Priority SOPs needed for scaling (30+ events/month, Event OS go-live)
- How SOPs should be maintained and linked in Event OS

It is derived from direct founder interviews (Ilyas) and tactical execution interviews (Zakir). **Founder business policy** is distinguished from **tactical execution (Zakir)**. Metrics not tracked are marked **Not Currently Measured**—never estimated. Undefined decisions are marked **Not Defined**.

**Intended audience:** Founders, product managers, engineers, AI agents, investors, and business leaders building Event OS SOP/checklist modules.

## 5. Priority SOPs for Scaling / Event OS

### Current State

No formal SOPs exist today (see [Section 3](#3-sop-inventory-by-domain)).

### Founder Policy — Priority order for 30+ events/month

Top 3 SOP priorities for scaling:

1. **Event Execution SOP**
   - Standardize event-day preparation, setup, quality checks, and completion process
2. **Packing & Inventory Movement SOP**
   - Standardize item selection, packing, loading, return, and storage process
3. **Customer Communication SOP**
   - Standardize customer updates, confirmations, changes, and important communication points

Rationale: highest impact on maintaining quality and consistency while increasing event volume.

### Future Vision

**Not Defined.**

## 6. Event OS SOP / Checklist Requirements

### Phase 1 Priorities (Founder + Operations)

Phase 1 should support **both**:

1. **SOP Document Library**
   - Store complete SOP documents for reference, training, and process updates
2. **Event-linked Checklists**
   - Use relevant SOP steps as checklists inside each event workspace
   - Examples: event execution checklist, packing checklist, customer communication checklist

Purpose: document library provides standard knowledge; event-linked checklists ensure execution consistency.

### Phase 1 (Must Have)

| Capability | Status |
|-----------|--------|
| SOP document library (reference/training) | Future Vision |
| Event-linked execution checklists (from priority SOPs) | Future Vision |
| Human-approved checklist completion (no auto-complete) | Future Vision |

### Guardrails

- SOPs support operations; do not replace founder/operations judgement.
- Checklist completion requires human confirmation.
